## Windows repair and acceptance gate

`CodexClient.close()` previously returned immediately after signalling its child. Auth and metadata cleanup inherited that behavior, allowing `app.close()` to finish while a child could still own the data-directory cwd. It now resolves after child **close**, including stdio; auth, discovery and validation await it. Auth rejects reconnection after shutdown. App close drains pending discovery before callers close SQLite/delete state. This is a defensible lifecycle repair; the exact historical EBUSY handle was not captured, so it is not claimed as a Windows reproduction.

The capability regression explicitly starts an auth child, awaits app close, checks child/stdio closure, rejects a new connection, then removes the directory **without retries**. Native Windows CI must pass this test plus daemon-lock/startup/transactions (now 15 tests in that step), all remaining steps, package generation and package/branding verification before Windows distribution promises change. Existing `windows.yml` includes this gate; both Windows and core main-push/PR workflows additionally run `demo:verify`. A package generated by CI still needs an actual installer-launch check before claiming launch support.

All development packages remain unsigned; macOS is not notarized. Signing is not a source-readiness prerequisite. Historical `IMPLEMENTATION.md` is not the current platform contract.
